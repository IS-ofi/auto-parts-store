# ADR-7: Інтеграційні й E2E-тести — справжня MongoDB в Docker, а не моки драйвера

## Status

Accepted

## Context

`orderRepository` має два шляхи (`withTransaction` на replica set і компенсація на standalone, `adr/adr5.md`). У `adr5` прямо сказано, що `withTransaction` «не перевірено в автоматичних тестах без replica set», а код mongo-репозиторіїв раніше виконувався лише проти імітації драйвера. Завдання 3 вимагає інтеграційні тести з піднятою залежністю й одну команду запуску.

## Decision Drivers

- Критичний ризик живе в поведінці БД (умовний `$inc`, унікальні індекси, транзакції, гонки), яку мок не відтворює (РПЗнП 7.7).
- Обидва шляхи `adr5` мають бути виконані реально.
- Одна команда на чистій машині; без зсуву портів і без доступу до чужих БД (РПЗнП 7.11).
- Мінімум коду, що існує лише для тестів (РПЗнП 7.5.1).

## Considered Options

### Варіант 1: Моки/фейки драйвера `mongodb`

- **Плюси:** швидко, без Docker.
- **Мінуси:** мок усе одно треба перевіряти на справжній БД; великий код лише для тестів; саме так `withTransaction` лишився неперевіреним.

### Варіант 2: `docker compose` із двома MongoDB — standalone і одновузловий replica set (обрано)

- **Плюси:** обидва шляхи `adr5` виконуються по-справжньому; ті самі образи, що й у продакшені; випадкові порти, tmpfs, `down -v` — нічого не лишається.
- **Мінуси:** потрібен Docker; старт replica set додає ~5–10 с; `directConnection=true` обов'язковий.

### Варіант 3: `mongodb-memory-server`

- **Плюси:** без Docker; підтримує replica set.
- **Мінуси:** завантажує бінарник MongoDB під час інсталяції (залежність від мережі й ОС); відрізняється від образу в продакшені. Не пробувався: оцінка за документацією.

## Decision

Варіант 2. Оркестрація — `scripts/test-all.js` (`npm test`); у CI з готовими service-контейнерами достатньо виставити `TEST_MONGO_URI` і `TEST_MONGO_RS_URI`. Ізоляція даних: окрема база на тестовий файл (`ap_it_<pid>_<ts>`), кожен тест працює зі своїми даними.

## Consequences

- **Позитивні:** закрито розрив «withTransaction не перевірено»; тест на збій запису після списання ловить видалення компенсації.
- **Негативні:** `npm test` вимагає Docker → `pre-push` має запускати `npm run test:fast`, а не `npm test`; `npm test` — перед PR і в CI.
- **Нейтральні:** `memory`-прогін лишається швидким шаром (і основою для мутацій).
