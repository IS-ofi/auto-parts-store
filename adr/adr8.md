# ADR-8: Мутаційне тестування — Stryker із command-runner на швидкому герметичному наборі

## Status

Accepted

## Context

Покриття показує виконання, а не перевірку (РПЗнП 7.8). Потрібен інструмент, що мутує код і дивиться, чи падають тести. Тести написані на вбудованому `node:test`.

## Decision Drivers

- Інструмент для JS: Stryker (PIT/mutmut/cosmic-ray — для інших мов).
- Не переписувати наявні `node:test`-тести заради інструмента.
- Мутації на всьому репозиторії — години; потрібні лише критичні модулі.

## Considered Options

### Варіант 1: Stryker + `command`-runner (`npm run test:fast`) (обрано)

- **Плюси:** працює з `node:test` без змін; набір `test:fast` герметичний (без БД і Docker) і швидкий.
- **Мінуси:** немає `perTest`-покриття: кожен мутант проганяє весь швидкий набір; результат без розрізнення `NoCoverage` (відрізняємо вручну за звітом покриття).

### Варіант 2: Перенести тести на Mocha/Jest/Vitest заради рідного runner-а Stryker

- **Плюси:** `perTest`, швидший прогін.
- **Мінуси:** переписування ~60 тестів і хелперів; нова залежність; ризик регресій заради інструмента.

## Decision

Варіант 1. `mutate`: `validation.js`, `errors.js`, `http.js`, `services/orderService.js`, `repositories/memory/index.js`. Mongo-репозиторії мутаціями не охоплено: їхні тести потребують Docker (години на мутанта). Їх захищають інтеграційні тести з прямою перевіркою БД; це свідома межа. Запуск: `npm run mutation`, у CI — nightly.

## Consequences

- **Позитивні:** відтворюваний звіт однією командою; класифікація вижилих у `reports/mutation-report.md`.
- **Негативні:** вижилі мутанти в `repositories/mongo/*` невидимі для цього звіту.
- **Нейтральні:** після цього ADR мутаційний прогін можна розширити, перейшовши на варіант 2.
