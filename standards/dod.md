# Definition of Done (DoD) — Інтернет-магазин автозапчастин

Цей документ визначає критерії готовності (Definition of Done) для задач і фіч у розробці інтернет-магазину автозапчастин (стек: HTML, CSS, Vanilla JS, нативний Node.js, MongoDB). Задача вважається виконаною та готовою до релізу лише тоді, коли вона задовольняє всі наведені нижче критерії.

---

## 1. Функціональність

- [ ] **Реалізація за специфікацією:** Функціонал повністю реалізований відповідно до вимог технічної специфікації (`spec.md`).
- [ ] **Крайні випадки (Edge Cases):** Оброблено типові помилки та невалідні сценарії (наприклад, порожній кошик, відсутність товару на складі (`stock === 0`), некоректні вхідні дані, помилки підключення до бази даних).
- [ ] **Кліент-серверна взаємодія:** Асинхронні запити з клієнта (Vanilla JS `fetch`) успішно обробляються нативним Node.js сервером, а дані коректно читаються, оновлюються або записуються в MongoDB через нативний драйвер.
- [ ] **Користувацький досвід (UX):** Забезпечено зворотний зв'язок для користувача (стани завантаження, індикатори, повідомлення про успіх або помилку).

---

## 2. Якість коду та підтримуваність

- [ ] **Конвенції коду:** Дотримано єдиного стилю написання коду, прийнятого в проєкті (читабельні назви змінних і функцій, модульна структура).
- [ ] **Статичний аналіз (Linting):** Код не містить попереджень (warnings) чи помилок від ESLint. Команда `npm run lint` завершується успішно з нульовим кодом помилки.
- [ ] **Форматування:** Весь змінений код відформатовано за допомогою Prettier. Команда `npm run format` не знаходить невідформатованих файлів.
- [ ] **Відсутність «сміття»:** У коді немає закоментованих блоків, зайвих `console.log` (окрім системного логування запуску сервера) та неіснуючих імпортів.

---

## 3. Автоматизація та інфраструктура

- [ ] **Запуск та стабільність:** Сервер стабільно запускається локально командою `npm run start` або в режимі розробки `npm run dev` (через вбудований у Node.js режим спостереження `--watch`).
- [ ] **Git-хуки (Husky):**
  - При спробі зробити `git commit` успішно спрацьовує хук `pre-commit`, який запускає `lint-staged` для перевірки й форматування лише змінених файлів.
  - При спробі зробити `git push` успішно спрацьовує хук `pre-push`, який виконує перевірку збірки/тестів (`npm test`).

---

## 4. Інтеграція та версійність

- [ ] **Чистота історії комітів:** Повідомлення комітів є осмисленими та структурованими (наприклад, у форматі `feat: додати обробку кошика`, `fix: виправити оновлення залишків`).
- [ ] **Робота з гілками:** Розробка ведеться у виділених гілках (feature branches), назви яких відображають суть задачі.
- [ ] **Code Review / Pull Request:** Зміни вливаються в головну гілку лише після проходження перевірки (Pull Request) та відсутності конфліктів злиття (merge conflicts).
