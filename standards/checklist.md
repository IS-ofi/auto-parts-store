# Чек-лист перевірки якості коду (Quality Checklist) — Інтернет-магазин автозапчастин

Цей чек-лист використовується для фінальної перевірки коду та готовності задач до злиття (Merge) у проєкті інтернет-магазину автозапчастин (стек: HTML, CSS, Vanilla JS, нативний Node.js, MongoDB).

---

## 1. Безпека та змінні середовища (.env)

- [ ] **Відсутність хардкоду:** Усі чутливі дані (рядок підключення до MongoDB, порти, секретні ключі сесій/токенів) винесені у змінні середовища і не записані «в лоб» у вихідний код.
- [ ] **Наявність `.env.example`:** У проєкті створено файл-шаблон `.env.example` без реальних секретів, який документує необхідні змінні для запуску.
- [ ] **Захист `.env` у Git:** Файл `.env` обов'язково додано до `.gitignore`, щоб уникнути його випадкового завантаження в репозиторій.
- [ ] **Валідація вхідних даних:** Усі дані, що надходять від клієнта через POST/PUT запити (наприклад, форма авторизації, створення замовлення, дані товарів), валідуються на сервері для запобігання ін'єкціям та некоректним типам даних.

---

## 2. Лінтери та форматування

- [ ] **Відсутність помилок ESLint:** Команда `npm run lint` виконується успішно та не виявляє жодних помилок чи попереджень (warnings/errors).
- [ ] **Дотримання конвенцій:** Код відповідає заданим правилам Flat Config та правилам глобальних змінних для Node.js та браузера.
- [ ] **Автоформатування (Prettier):** Увесь код відформатовано відповідно до `.prettierrc`. Команда `npm run format` не змінює жодних файлів (усе вже відформатовано).
- [ ] **Чистота коду:** У файлах відсутні зайві закоментовані шматки коду, непотрібні імпорти та зайві `console.log` (за винятком системного логування роботи сервера).

---

## 3. Запуск сервера та працездатність

- [ ] **Старт в продакшн-режимі:** Сервер успішно запускається без помилок за допомогою команди `npm start`.
- [ ] **Режим розробки:** Налаштування команди `npm run dev` (із використанням вбудованого у Node.js прапорця `--watch`) працює коректно та перезапускає сервер при зміні файлів.
- [ ] **Підключення до бази даних:** Сервер успішно встановлює з'єднання з MongoDB через нативний драйвер і коректно обробляє помилки підключення (наприклад, якщо БД недоступна).
- [ ] **Ендпоінти та клієнт:** Усі реалізовані API Endpoints коректно обробляють запити від клієнтської частини (Vanilla JS `fetch`), повертаючи очікувані статуси та структуру JSON-відповідей.

---

## 4. Гілки та Git (Workflow)

- [ ] **Очищення гілки:** Робота над фічею велася у виділеній гілці (feature branch) із зрозумілою назвою, що відображає суть задачі.
- [ ] **Чистота комітів:** Повідомлення комітів написані зрозумілою мовою та слідують єдиному стилю.
- [ ] **Робота Git-хуків (Husky):**
  - При спробі виконання `git commit` автоматично спрацьовує хук `pre-commit` і `lint-staged`, перевіряючи та форматуючи лише змінені файли.
  - При спробі виконання `git push` успішно проходить перевірка хука `pre-push`.
- [ ] **Відсутність конфліктів:** Перед створенням Pull Request гілка оновлена актуальним станом з головної гілки проєкту, конфлікти злиття відсутні.
